# excel-testcase-18col

生成符合企业 **18 列标准格式**的测试用例 Excel：用例套件 + 测试用例双层结构，平台可直接导入。支持基线驱动（文案/链接抽成单一数据源）与步骤↔预期 1:1 编号配对。

## 安装

方式一，命令行安装：

```bash
npx skills add <your-github-id>/<your-repo> --skill excel-testcase-18col
```

方式二，手动安装：把整个 `excel-testcase-18col/` 目录复制到你的 skills 目录：

| 客户端 | 路径 |
|---|---|

| Claude Code | `~/.claude/skills/` |
| Codex | `~/.codex/skills/` |

## 它解决什么问题

用例表和测试平台对不上，是发版前最常见的返工来源：

- 平台导入模板的选型列只能取 `Y/N`、`有效/无效`，写成中文「是/否」「待评审」会被**静默判为 `N`**——导入后整批用例变成「非基础用例 + 只能在现场测试」，不报错、不回滚。
- 步骤和预期条数不等，评审时对不上号，执行时漏验。
- 文案、链接散落在每条用例里，改一次需求要全文替换。

本技能把「18 列结构 / 套件编号树 / 质量红线 / 生成后机器校验」固化成规范，并内置官方平台导入模式，让生成物直接可导入。

## 快速开始

```text
按 18 列企业模板生成教务模块的测试用例，用例套件按功能模块划分
```

```text
用基线驱动模式生成用例：文案和链接抽到 baseline.json，输出三表
```

```text
按 18 列模板导出，用来导入平台
```

最后一句会触发**导入模式硬约束**：全部用例 `可测试=Y`、`基础用例=Y`、`状态=有效`，类型只用 8 类枚举，物理固定 18 列，套件树按原有功能模块建立。

## 三种产出模式

| 模式 | 适用场景 | 产物 |
|---|---|---|
| 通用 18 列 | 内部评审、留档 | 测试用例表（可含第 19 列「覆盖路径」） |
| 基线驱动（推荐） | 文案/链接易变 | 三表：测试用例 / 文案基线 / 链接基线 |
| 导入模式 | 导入官方用例平台 | 在官方模板副本上填数据，固定 18 列，保留双 sheet + 6 列数据验证 |

## 内置脚本

| 脚本 | 用途 |
|---|---|
| `scripts/gen_testcases_template.py` | 18 列标准结构生成模板（套件树 + 用例行 + 样式） |
| `scripts/gen_baseline_template.py` | 基线驱动生成模板：`baseline.json` 单一数据源 + 步骤↔预期 1:1 配对 + 三表输出 |
| `scripts/gen_platform_import.py` | **导入模式专用**：在官方模板副本上填数据，自动写 `Y/Y/有效`、8 类枚举转换、套件树、18 列，并内置 6 项机器校验（含选型合规） |

## 质量红线（18 条）与机器校验（6 项）

红线在生成前逐条自检，机器校验在生成后跑脚本卡口。要点：

- 步骤具体可执行、含导航路径，不暴露代码字段
- **禁止编造虚构异常**（最高优先级）
- 步骤 ↔ 预期严格 1:1 编号配对，纯导航步骤预期写 `-`
- 用例 → 套件归属一致：`归属套件 == 编号 // 100`，且套件实体真实存在
- 步骤/预期不得写「合并验证」等内部标注，用例间关系放「描述」列
- **列取值只用官方枚举**，`G==Y && H==Y && I==有效` 覆盖率须 100%

完整清单见 `SKILL.md`。
