# Phase 1 需求分析追问模板

## 触发条件

当需求描述满足以下任一条件时，启动追问流程：
- 少于 50 字
- 缺少用户角色描述
- 缺少异常处理说明
- 缺少关联模块说明

## 追问话术模板

### 礼貌开场

```
收到需求：「{原始需求}」

我来帮你做完整的测试分析。在开始前，有几个细节需要确认，这样生成的测试用例会更准确：
```

### 分组追问（按缺失项选择）

**[用户角色缺失]**
```
1️⃣ 这个功能面向哪类用户？
   - 是否有角色区分（普通用户/管理员/访客）？
   - 不同角色的操作权限有什么区别？
```

**[前置条件缺失]**
```
2️⃣ 使用这个功能前，用户需要满足什么条件？
   例如：必须已登录 / 需要实名认证 / 必须完成某步骤
```

**[异常处理缺失]**
```
3️⃣ 遇到以下情况时，系统应该怎么处理？
   - 网络超时/断开
   - 提交的数据不合法
   - 操作时会话过期
   - 多人同时操作同一数据
```

**[关联模块缺失]**
```
4️⃣ 这个功能会牵涉到哪些其他模块？（多选）
   □ 用户权限/角色控制
   □ 操作日志/审计
   □ 消息通知（短信/邮件/站内信）
   □ 文件上传/存储
   □ 数据统计/报表
   □ 搜索功能
   □ 第三方接口
   □ 其他：___
```

**[成功标准缺失]**
```
5️⃣ 什么情况下算这个功能"正常工作"了？
   用户看到什么界面/收到什么反馈/数据有什么变化？
```

**[边界条件缺失]**
```
6️⃣ 有没有数量/长度/时间的限制？
   例如：每天最多提交10次 / 标题不超过50字 / 有效期7天
```

## 需求假设模板

当用户无法提供某些信息时，使用以下假设并标注：

```markdown
> ⚠️ 以下为测试假设，请在用例评审时确认：
> - 假设A：未说明角色，默认按"已登录普通用户"设计测试用例
> - 假设B：未说明并发处理，默认需要测试乐观锁/幂等性
> - 假设C：未说明日志需求，默认关键操作需记录操作日志
```
