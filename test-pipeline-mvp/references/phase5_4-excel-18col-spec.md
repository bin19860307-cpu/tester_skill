# Phase 5.4 — 18 列 AITest 企业模板规范（内置版）

> 本文件是 Phase 5.4「18 列企业模板模式」的完整规范。技能包自包含——不需要额外安装任何技能即可按本规范生成 18 列 Excel。
> 与 Phase 5.1 的 **12 列标准结构二选一，物理列不同、不可混用**。

---

## 1. 双层结构

一个 sheet 内同时存在两类实体，用 **A 列「实体标识」**区分：

| 实体 | A 列取值 | 说明 |
|---|---|---|
| 用例套件 | `用例套件` | 只做分组，不含步骤/预期 |
| 测试用例 | `测试用例` | 真正可执行的用例行 |

先出套件行，再出用例行；用例通过 **D 列「归属套件」** 挂到套件上。

## 2. 18 列结构

| 列 | 列名 | 实体=用例套件 | 实体=测试用例 |
|----|------|---------------|---------------|
| A | 实体标识 | `用例套件` | `测试用例` |
| B | 编号 | 整数（1 / 101~） | 5 位整数（10101~） |
| C | 名称 | 套件名称 | 用例名称 |
| D | 归属套件 | 父套件编号（顶层=0，一级=1） | 所属套件编号 |
| E | 版本 | 留空 | 留空（模板说明：不必填写） |
| F | 类型 | 留空 | **8 类枚举之一**：正常流程 / 异常流程 / 性能测试 / 集成测试 / 回归测试 / 遍历测试 / 冒烟测试 / 其他 |
| G | 可测试 | 留空 | **`Y`**（= 实验室可以测试） |
| H | 基础用例 | 留空 | **`Y`**（= 基础用例，见红线 6） |
| I | 状态 | 留空 | **`有效`** |
| J | 预置条件 | 留空 | 多条按 `1. 2. 3.` 条列，`\n` 分隔 |
| K | 测试过程 | 留空 | 步骤，`\n` 分隔 |
| L | 接收标准 | 留空 | 预期，与 K 严格 1:1 编号 |
| M | 创建人 | 留空 | 留空（模板说明：不必填写） |
| N | 创建时间 | 留空 | 留空（模板说明：不必填写） |
| O | 描述 | 可选备注 | 可选备注 |
| P | 脚本名称 | 留空 | 留空 |
| Q | 验证话单 | 留空 | **`N`（不检查）**，见第 7 节 |
| R | 信令流程 | 留空 | 留空 |
| S | 覆盖路径 | 留空 | `节点A→节点B→节点C`（可选，对应 Phase 1.5 节点 ID） |

> S 列是**可选第 19 列**：配合 Phase 1.5 流程图时启用；**导入官方平台时必须省略，保持物理 18 列**（多一列会导致导入列错位）。
> **G / H / I / Q 四列的取值不是自由文本**，只能取上表加粗值。写成中文「是/否」「待评审」会被导入端静默丢弃并落到默认值——完整后果见第 7 节。

## 3. 编号规则

```
顶层套件：编号=1，归属套件=0
一级套件：编号=101/102/103...，归属套件=1
测试用例：编号=10101/10102...，前 3 位 = 所属套件编号
```

**红线校验**：每条用例的「归属套件」必须等于 `编号 // 100`，且该编号在套件实体中真实存在。

## 4. 基线驱动模式（推荐用于文案/链接易变场景）

把「测试逻辑」与「测试数据」解耦：

- 单一数据源 `baseline.json`：文案 `{{T:ID}}`、链接 `{{L:ID}}` 占位符引用
- 步骤改为 `[步骤, 预期]` 配对列表，渲染时严格 1:1
- 纯导航步骤的预期传 `-`，渲染为 `N. -`（保持配对又不编伪预期）
- 三表输出：**测试用例 / 文案基线 / 链接基线**

改文案或换链接时只改 JSON、重跑生成器，用例自动同步。

## 5. 质量红线（生成前逐项自检）

1. **名称体现测试点，步骤不重复**：名称直接点明验证点；步骤只写操作与导航，不复述测试点。
2. **步骤具体可执行**：必须含导航路径（菜单/页面/按钮），禁止「进入详情页」这类模糊表述。
3. **纯文字表述，不暴露代码字段**：禁止 `school_id` / `config.model` / `<agentId>` 等写法，改业务术语。
4. **禁止编造虚构异常**（最高优先级）：先判断该异常在真实业务是否会发生；前置不满足时应写「前置条件负向」，而非「配置了但异常」。
5. **前置条件真实且同套件可比**：同套件用例基线一致，差异只落在被测变量。
6. **基础用例标记准确**：`基础用例` 是**用例集属性**（是否纳入基础回归集），不是场景正/反向属性——全部用例一律 `Y`，异常/边界/攻击性用例同样是基础用例。**禁止「正向标是、异常标否」**（旧口径已废止，见第 7 节 ②）。
7. **接收标准具体可验证**：写清具体表现（文案、格式、状态变化），禁止「功能正常」。
8. **单值/多值语义对齐需求文案**：变量是单值还是多值（顿号分隔）必须明确。
9. **归属聚焦、按需分组件**：不混入无关用例；多类型按类型拆子套件。
10. **需求缺口显式标注**：不明确处列为「需求缺口/待确认」，用例中标记为假设。
11. **角色/权限维度系统性覆盖**：基于角色权限矩阵构造，覆盖权限差异与豁免场景。
12. **生成后完整性自检**：需求点覆盖 / 正反异常齐备 / 步骤可执行 / 预期可验证 / 权限覆盖。
13. **步骤与预期 1:1 编号对应**：每条步骤都必须有编号一致的预期；纯导航步骤预期传 `-`（渲染 `N. -`）。生成器须断言 步骤数 == 预期数。
14. **预期具体自洽，禁止引用设计稿/截图**：不得写「与设计稿一致」，须把真实文案写进预期；多元素用「①A — a；②B — b」配对。
15. **预置条件条列化**：多条件必须 `1. 2. 3.` 编号逐条，禁止分号拼成一段。
16. **用例→套件归属一致性**（机器校验）：逐条核对归属列是否真指向所属套件，不能只数套件实体数量。
17. **步骤与预期禁写内部引用标注**：不得写入「（合并验证：EC10605）」等元注释；用例间关系放「描述」列。
18. **列取值只用官方枚举**（机器校验）：A/F/G/H/I/Q 六列逐行落在第 7 节 ① 的合法值集合内，`G==Y && H==Y && I==有效` 覆盖率须 100%；任何一行越界即阻塞交付。

## 6. 生成后机器校验（6 项，必须全过）

| # | 校验项 | 判据 |
|---|--------|------|
| 1 | 归属一致性 | 每条用例 `归属套件 == 编号 // 100`，且套件存在 |
| 2 | 占位符残留 | 全文无 `{{T:` / `{{L:` 未展开残留 |
| 3 | 步骤预期 1:1 | 每条用例 步骤行数 == 预期行数（含 `-`） |
| 4 | 编号唯一 | 套件编号、用例编号均无重复 |
| 5 | 内部引用 | 「测试过程」「接收标准」中无「合并验证」「已由主用例」等字样 |
| 6 | **选型合规**（★ v2.13） | A/F/G/H/I/Q 逐行在枚举内；`G==Y && H==Y && I==有效` 占比 100%；物理列数 == 18 |

任一项不过 → 修正后重跑校验，不得带着失败项交付。

## 7. 官方平台导入模式硬约束（★ v2.13 新增）

> 事故背景（2026-11-09 实测）：生成的 Excel 写入中文「是/否」「待评审」「功能测试」，而平台导入模板的数据验证只收 `Y/N`、`有效/无效` 和 8 类固定类型。**非法值被静默判为 `N`**，导入后全部用例显示为「非基础用例 + 只能在现场测试」，等于整批用例不可用——且不报错、不回滚，人工不逐行核对发现不了。

**① 列取值硬约束（全部用例，无一例外）**

| 列 | 唯一合法值 | 平台界面对应 | 写成别的会怎样 |
|----|-----------|-------------|---------------|
| A 实体标识 | `用例套件` / `测试用例` | 套件 / 用例 | 该行不被识别 |
| F 类型 | `正常流程`/`异常流程`/`性能测试`/`集成测试`/`回归测试`/`遍历测试`/`冒烟测试`/`其他` | 类型按钮组（单选） | 「功能测试」「异常测试」等自造值 → 判 `其他` |
| G 可测试 | **`Y`** | 实验室可以测试 | `N` 或中文「是」→ 只能在现场测试 |
| H 基础用例 | **`Y`** | 基础用例 | `N` 或中文「否」→ 非基础用例 |
| I 状态 | **`有效`** | 有效 | 「待评审」→ 无效 |
| Q 验证话单 | **`N`（不检查）** | 验证话单按钮组 → 不检查 | `Y` 表示需检查话单 |

**② 禁止按用例性质区分基础用例**：`基础用例` 是**用例集属性**（是否纳入基础回归集），不是场景正/反向属性。异常流程、边界、攻击性用例同样属于基础用例。旧版「正向标是、异常标否」是错误口径，已废止。

**③ 工作表与数据验证**：保留官方模板两张 sheet（`测试用例表` + `填写说明`），并为 A/F/G/H/I/Q 六列写入下拉数据验证（`"用例套件,测试用例,不填"` / 8 类 / `Y,N` / `Y,N` / `有效,无效` / `Y,N`），范围 `第2行:65536行`。应**直接在官方模板副本上填数据**，不另建工作簿，以确保列序、验证与说明页完全一致。

**④ 套件树与编号**：每行一个套件或用例，用 `编号` + `归属套件` 组成树/森林；归属套件不存在于表中者即为根节点（导入时挂到执行导入的套件下）。**套件行只填 A/B/C/D/O 五列**，其余留空；**用例行除 E/M/N 外按属性填写**。B/D 必须是数字。

**⑤ 名称前缀**：名称若以 `【基础用例】` / `【非基础用例】` 开头，前缀会被平台忽略。**不要在名称中写这两种前缀**——基础属性完全由 H 列决定。

**⑥ 类型映射（由 Phase 3 四选一类型标签转换）**

| Phase 3 类型 | 18 列 F 列取值 |
|---|---|
| 正常流程 | 正常流程 |
| 异常流程 / 异常流程（攻击） | 异常流程 |
| 冒烟测试 | 冒烟测试 |
| 遍历测试 | 遍历测试 |
| 性能验证组用例 | 性能测试 |
| 兼容性验证组用例 | 其他 |
| 端到端（集成联动）用例 | 集成测试 |
| 多标签（如 冒烟测试；遍历测试） | 取主标签（第一个） |

**⑦ Q 列口径已闭环**：`验证话单 = N / 不检查` 为 2026-11-09 用户明确确认的最终口径（曾列为待确认，现已关闭）。生成器校验中 `Q != N` 直接阻塞，不提供开关。

**⑧ 生成器必须做的选型断言**：生成后逐行校验 G/H/I/F/Q 在枚举内，且 `G==Y && H==Y && I==有效` 的用例占比 100%；任何一行不合规即阻塞交付（并入第 6 节第 6 项）。
