## v2.8.0（2026-11-03）— 官方平台导入模式硬约束（规则版 v2.13）

> 承接一次真实导入事故：生成的 18 列 Excel 写入中文「是/否」「待评审」「功能测试」，而平台导入模板的数据验证只收 `Y/N`、`有效/无效` 和 8 类固定类型。**非法值被静默判为 `N`**，导入后全部用例变成「非基础用例 + 只能在现场测试」——不报错、不回滚，人工不逐行核对发现不了。

| 项 | 修复前 | 修复后 |
|---|---|---|
| 可测试 / 基础用例 / 状态 | `是` / `是·否`（按正反向区分） / `待评审` | **`Y` / `Y` / `有效`**——基础用例是**用例集属性**，异常/边界/攻击性用例同样是基础用例 |
| 类型列 | `功能测试 / 异常测试 / 边界测试`（自造值） | **8 类枚举**：正常流程 / 异常流程 / 性能测试 / 集成测试 / 回归测试 / 遍历测试 / 冒烟测试 / 其他，附 Phase 3 四选一标签映射表 |
| 验证话单 | 留空 | **`N`（不检查）**，口径已闭环，校验中 `Q != N` 直接阻塞 |
| 物理列数 | 可选第 19 列「覆盖路径」 | 导入模式**固定 18 列**，第 19 列仅限工作区内部评审产物 |
| 套件树 | 未约束 | 按原有功能模块建立（顶层 → 功能模块 → 用例），不得按测试类型/风险维度重组 |
| 名称前缀 | 未约束 | 禁止 `【基础用例】`/`【非基础用例】`，基础属性由 H 列决定 |
| 数据验证 | 未要求 | 在官方模板副本上填数据，保留双 sheet + A/F/G/H/I/Q 六列下拉验证 |
| 红线 / 机器校验 | 17 条 / 5 项 | **18 条 / 6 项**，新增「列取值只用官方枚举」与「选型合规覆盖率 100%」门禁 |

**指标影响**：生成口径变化（选型列不再可自由填写），三率基线不变（`baseline/eval-result.json` 仍为 留存 25.0% / 修改 62.5% / 删除 12.5% / 缺口 12.5%），`baseline/demo/` 示例数据无需重建。

**顺带修复**：`baseline/skill-version.json` 的 `files_snapshot` 仍指向已改为 CSV 的 xlsx，已同步为 `first-run.csv` / `final.csv`。
