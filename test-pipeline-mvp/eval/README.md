# 固定基准测试集（eval）

> 本目录承载 AI 用例生成评测的**固定基准测试集**，用于量化 `test-pipeline-mvp` + `excel-testcase-18col` 的产出质量、支撑版本基线与控制变量迭代。
> 设计来源：《AI用例生成评测体系量化方案》（2026-08-13 用户确认 5 项决策）。

## 1. 基准集选取标准（决策 1）

- **按冒烟用例走**：只收最核心、最稳定的流程。
- **仅正向（主）流程**：起步阶段不收异常/边界/负向，聚焦"AI 能否一次把正向主流程写对"。
- **稳定性**：需求文档一旦纳入，不频繁修改；否则跨迭代评测不可比。
- **覆盖度**：起步 8–12 条，覆盖接口类 / UI类 / 权限类，均为正向主流程。

## 2. 文件规范

```
eval/
├── README.md                  # 本文件
├── req-NNN-<模块>-<核心正向流程>.md   # 需求文档（稳定，不频繁改）
└── ...
```

- `req-NNN-*.md` 只放**需求描述**（背景、角色、前置、主流程步骤、预期），不放用例。
- "标准答案"不需要手写——它就是流水线在该需求上跑出的**最终生成用例（封版 final xlsx）**（决策 2）。

## 3. 度量指标（决策 3）

以「首跑生成用例」总数 N 为分母：

| 指标 | 定义 | 公式 |
|------|------|------|
| **留存率（≈有效率）** | 首跑到封版未被改动、未被删的用例占比 | 留存数 / N |
| **修改率** | 首跑到封版被测试人员改动的用例占比 | 修改数 / N |
| **删除率** | 首跑到封版被测试人员删除的用例占比 | 删除数 / N |

计算：`../scripts/eval_metrics.py --first <首跑.xlsx> --final <封版.xlsx>`

## 4. 使用流程

1. **建集**：把核心正向流程需求写入 `req-NNN-*.md`。`req-001-班级管理-新建班级正向流程.md` 已是**真实冒烟需求**（2026-08-13 确认）；`req-002-权益控制-绑定权益正向流程.md` 仍为种子示例，待替换为真实需求。
2. **首跑**：对每个 `req-*.md` 跑完整流水线，导出首跑 xlsx（即"首跑生成用例"）。
3. **评审改/删**：测试人员评审，产生封版 final xlsx（即"标准答案"）。
4. **算指标**：`eval_metrics.py` 对比首跑 vs 封版 → 输出 `eval-result.json`（留存率/修改率/删除率）。
5. **冻结基线**：封版前用例不再变动 + 测试人员最终比对确认后，把 `skill-version.json` + `model-version.json` + `eval-result.json` 存入 `../baseline/`，并写一条 `../CHANGELOG.md`。
6. **控制变量迭代**：每次只改一个变量 → 固定集全量重跑 → 对比基线 → 无论改进/退步都入 CHANGELOG。

> **首个真实运行（2026-08-13）**：`req-001` 已端到端跑通，首跑/封版两版 xlsx 存于 `eval/runs/run-20260813-班级管理-新建班级/`，基线快照已冻结于 `../baseline/`（pilot，模拟评审，待真实测试人员确认）。度量脚本已兼容 18 列 AITest 企业模板（通过 `--entity-col 实体标识 --entity-val 测试用例` 过滤套件行）。
