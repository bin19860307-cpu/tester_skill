# Bug 列表分析（测试报告素材生成）

## 适用场景

当用户提供一份或多份 **Bug / 缺陷列表 Excel**（通常来自 TAPD、禅道、云效等系统的导出），
并要求「做下 bug 分析」「分析这份缺陷列表」「生成测试报告的 bug 分析章节」时使用本 Skill。

输出目标：一份**文字版**分析报告，可作为测试报告中「Bug 分析」章节的现成素材。

---

## 输入要求（Excel 列）

脚本通过**列名别名匹配**自动识别，不要求固定表头。常见列（中英文均可）：

| 分析维度 | 期望列名（任一即可） |
|----------|----------------------|
| 唯一编号 | 编号 / bug编号 / ID |
| 标题 | 标题 / 摘要 / subject |
| 严重程度 | 严重程度 / bug级别 / 优先级 |
| 缺陷类型 | bug类型 / 缺陷类型 / 类型 |
| 状态 | 状态（已关闭 / 已挂起 / 待解决 …） |
| 激活次数 | 激活次数 / 打回次数 / 返工次数 |
| 产生版本 | 产生版本 / 发现版本 / 版本 |
| 解决版本 | 解决版本 / 修复版本 |
| 模块 | 模块 / 所属模块 / 功能模块 |
| 创建人 | 创建人 / 提交人 / 报告人 |
| 解决者 | 解决者 / 处理人 / 修复人 |
| 处置方式 | 处置方式 / 解决方案 |
| 创建时间 | 创建时间 / 提交时间 |
| 解决时间 | 解决时间 / 关闭时间 |

> 缺失某些列不会中断分析，对应维度会提示「跳过」。修复周期需要同时存在「创建时间」与「解决时间」。

## 工作流程

### 扩展功能

- `--html` 生成自包含 HTML 报告（Chart.js 已内联进单文件，无需联网、不依赖外部 CDN，可直接打开/分享）。
- `--infer-module` 自动从 Bug 标题提取模块名并填充「模块」列，适用于原始数据缺失的情况。
- 组合使用示例：`python analyze_bugs.py bug.xlsx --html report.html --infer-module`。
- 生成的 HTML 报告每个图表下方内置「复制图片」按钮：点击优先将图表写入剪贴板（localhost 安全上下文可用），复制失败则自动新标签打开供手动保存，不做批量全量导出。

### Step 1：确认输入
读取用户给出的 `.xlsx` 路径。若文件含多个 sheet，脚本自动选取**行数最多**的表（缺陷数据通常在此）。
如需指定 sheet，使用 `--sheet 表名`。

### Step 2：运行分析脚本
执行 `scripts/analyze_bugs.py`：

```bash
python "<skill>/scripts/analyze_bugs.py" "D:/下载/bug列表 (1).xlsx"
```

- 输出标准文字版分析（十二个维度，见下文）。
- 如需与历史版本对比，追加 `--baseline 历史列表.xlsx`，脚本会额外打印对比速览。
- 若脚本缺失 pandas，先 `pip install pandas openpyxl`（建议在隔离的 venv 中安装）。

### Step 3：套用报告模板
将脚本输出按 `references/report_template.md` 的结构重组为正式章节：
- 保留所有**数据表**（严重程度、类型、返工、修复周期、版本、模块、解决者、待处理清单）。
- 每个维度补充一句**结论**（模板已给出结论写法示例，需结合项目实际措辞）。
- 删除脚本中的分隔线 / 标记行，改为规范的小节标题。

### Step 4：校验与补充结论
- **数字自洽**：总数 = 各状态之和 = 各严重程度之和。
- **结论有依据**：每条结论必须对应脚本中的某个数值（如「严重占比 2.2%」→「核心功能受阻风险低」）。
- **补充风险项**：脚本列出的「待处理缺陷清单」必须进报告，并写明风险提示。
- **版本对比**（如有）：将本版本与基线关键指标列入对比表，点明差异与原因。

## 分析维度（脚本覆盖）

1. 基本概况 / 状态分布（总数、已关闭率）
2. 缺陷严重程度分布
3. 缺陷类型分布
4. 返工情况（激活次数 → 一次解决率、返工率）
5. 修复周期分析（均值 / 中位数 / 分布区间）
6. 版本分布（产生版本 TOP、解决版本 TOP）
7. 功能模块分布 TOP
8. 人员分布（提交人、解决者）
9. 处置方式分布
10. 严重程度 × 修复效率
11. 解决者修复效率
12. 待处理缺陷清单

---

## 关键指标定义

| 指标 | 计算方式 |
|------|----------|
| 已关闭率 | 状态含「关闭」的 Bug 数 / 总数 |
| 一次解决率 | 激活次数 = 0 的 Bug 数 / 总数 |
| 返工率 | 激活次数 ≥ 1 的 Bug 数 / 总数 |
| 平均修复周期 | mean(解决时间 − 创建时间)，单位天，仅统计日期有效的已解决项 |
| 修复周期区间 | ≤1 / 2–3 / 4–5 / 6–10 / >10 天（互不重叠） |

---

## 注意事项

1. **修复周期符号**：仅统计「解决时间 ≥ 创建时间」的合法日期对；异常日期（未来解决、缺失）会被排除并提示。
2. **版本号归一**：产生版本与解决版本通常带前缀（如 `chufa-5.0.0.2`），保留原始值即可，不要自行截断。
3. **结论克制**：先给数据，再下结论；不臆造脚本未覆盖的指标（如没有「严重程度×模块」交叉列就别硬编）。
4. **对比口径一致**：对比两个版本时，确保两份列表的列定义、统计口径一致，否则对比表可能误导。
5. **文字版优先**：本 Skill 产出为文字版，便于直接粘贴进测试报告；如需图表版，另行用前端/文档工具生成。
