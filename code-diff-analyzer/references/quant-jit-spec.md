# 量化风险评分 & JIT 缺陷预测（apex 能力整合）

> 把 apex-diff-analyzer 的 Step 5c 量化评分 + Step 5d JIT 预测，以可复用引擎形式落入 code-diff-analyzer。
> 引擎：`scripts/quant_jit_risk.py`；注入：`scripts/gen_quant_jit.py`。

## 1. 两种评分模式

| 模式 | 触发 | 维度 | 历史度量权重 |
|------|------|------|------|
| 静态 5 维 | 无 historical_metrics（离线 compare 模式） | 基础风险/变更规模/模块跨度/核心模块占比/变更密度 | — |
| 增强 10 维 | 提供 historical_metrics 或 `--service` 自动取数 | 上述 5 维 + 历史Bug频率/代码流失率/修改频率/作者经验/距上次修改 | 25%（≈核心模块占比） |

两种模式各维得分上限均为 5 → `Risk ∈ [0,5]`；`百分制 = Risk/5*100`。
等级：>=75 🔴高风险；>=50 🟡中风险；其余 🟢低风险。

## 2. 维度映射（升序边界 → 得分）

| 维度 | 边界(asc) | 得分 |
|------|-----------|------|
| 基础风险 | high=5 / medium=3 / low=1 | — |
| 变更规模(行) | [20,50,100,200] | [1,2,3,4,5] |
| 模块跨度(文件) | [1,2,3,5,10] | [1,2,3,4,5] |
| 核心模块占比(%) | [10,30,50] | [1,3,4,5] |
| 变更密度(行/文件) | [5,10,30,50] | [1,2,3,4,5] |
| 历史Bug频率(%) | [0,10,40,70] | [1,2,4,5] |
| 代码流失率 | [0,2,5,10] | [1,2,4,5] |
| 修改频率(次) | [0,5,20,50] | [1,2,3,5] |
| 作者经验(次，反向) | [0,10,50,200] | [5,3,2,1] |
| 距上次修改(天) | [0,30,90,365] | [1,2,3,5] |

## 3. 权重

- 静态：`base 0.30 / size 0.20 / span 0.15 / core 0.25 / density 0.10`（合计 1.0）
- 增强：`base 0.20 / size 0.15 / span 0.10 / core 0.20 / density 0.05 / buggy 0.15 / churn 0.10 / modfreq 0.03 / authorexp 0.01 / dormancy 0.01`（合计 1.0）

## 4. JIT 缺陷预测

核心模式（命中即 🔴 最强缺陷指示器）：认证/权限/登录/禁用、支付/订单/交易/权益、路由/导航、配置/常量、降级/版本。
+ 规模 >400 行 → 🟡 拆 PR；跨文件 >10 → 🔴；数据格式变更 → 🔴。
🔴 命中数 >=2 → 高风险预测；==1 → 中等；否则 → 低。
效果参考：Top-20% 高风险变更覆盖 75%-88% 真实缺陷，AUC 0.72-0.83（CC2Vec/JITLine, Zhou et al. 2021）。
**局限**：规则引擎推断，非 ML 模型；权重应按项目数据校准。

## 5. 运行

```bash
python scripts/gen_quant_jit.py --report R.html --stats stats.json
python scripts/gen_quant_jit.py --report R.html --stats stats.json --service portal-backend --workspace <ws>
```

注入占位符 `<!-- QUANT_JIT_SECTION -->`（模板已加），片段以 `<!-- QUANT_JIT_START/END -->` 包裹，幂等可重复。
